CCDV-F SIM-02 — Document Pipeline: Batch, Streaming and Caching

How to use this: read the scene, then work through the decisions on paper, or paste the scene and the decisions list (not the answer key) into Claude and ask it to run the simulation one decision at a time with no hints. Open the coach key only when you've finished.

Primary domains: 2 Applications and Integration, 5 Model Selection and Optimization · Decisions: 10 · Time: 20 min

Scene (original, written from the official objectives)

You're the developer on a freight company's document team. Two jobs use Claude on the same scanned delivery forms. The back-office job extracts fields from a backlog of tens of thousands of forms for a month-end audit that nobody reads until next week. The customer portal lets a driver upload a photo of one form and see a plain-English summary on screen. Both jobs send the same three pages of extraction instructions and a JSON schema on every call, and the bill is climbing.

The decisions (answer these before you open the key)

  1. How to run the month-end backlog
  2. Drivers stare at a blank portal screen for many seconds
  3. How to send the driver's photo
  4. The same instructions and schema are paid for on every call
  5. Cache reads stay near zero. The system prompt starts with today's timestamp and a request ID
  6. Most forms are clean and typed; a few have long handwritten damage notes
  7. Some summaries end mid-JSON and the parser crashes
  8. Finance wants cost per customer
  9. The portal gets HTTP 429 errors at the morning rush
  10. A stream sends an overloaded_error event partway through

Scoring: 8 or more is a pass. Decisions 1 and 4 are the heart of the scenario: match the API to who is waiting (batch when nobody is, streaming when a person is), and cache the stable prefix, put what changes last.
