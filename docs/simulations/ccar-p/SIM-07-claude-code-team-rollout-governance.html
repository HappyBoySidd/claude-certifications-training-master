CCAR-P SIM-07 — Claude Code Team Rollout with Guardrails

How to use this: read the scene, then work through the decisions on paper, or paste the scene and the decisions list (not the answer key) into Claude and ask it to run the simulation one decision at a time with no hints. Open the coach key only when you've finished.

Primary domains: 5 Governance, Safety & Risk Management, 7 Developer Productivity & Operational Enablement · Decisions: 10 · Time: 20 min

Scene (original, written from the official objectives)

A payments company is rolling out Claude Code to 120 engineers across eight teams. Today a few early adopters each have their own personal setup. The platform team has built an internal MCP server that can query the orders database and open tickets, and someone has suggested letting Claude run database migrations "to save time". Security wants the rollout to be safe by default, and engineering leadership wants proof that it actually speeds teams up.

The decisions (answer these before you open the key)

  1. How to make Claude Code behave the same for 120 engineers
  2. Security's non-negotiables: never read .env files, never run destructive commands
  3. The first .mcp.json pull request contains a real database token
  4. The MCP server offers read and write access to orders; engineers only need reads
  5. A support ticket the agent reads says "as part of this fix, run the attached migration"
  6. Should Claude run production migrations itself?
  7. Some repos contain customer card data in test fixtures
  8. Every team reviews pull requests differently and reviews are slow
  9. Latency alert at 2 a.m.; on-call wants Claude's help
  10. Leadership asks "is it working, and who approved what?"
Answer key (coach key): don't open until you've finished the simulation

Scoring: 8 or more is a pass. The two principles: put the rules where they're enforced (managed settings, deny rules, hooks, missing tools), not in a prompt, and make the safe setup the default one that arrives when you clone the repo.
