Domain 1: Agentic Architecture and Orchestration (27%, 32 cards)

1.1 Design and implement agentic loops for autonomous task execution

Study objective 1.1 before or after these cards.

Card 1 · Objective 1.1

In an agentic loop, which field tells your code whether to run a tool or stop?

Show answer to card 1

stop_reason: keep looping on "tool_use", stop on "end_turn". It is the model's own structured signal, so no guessing is needed.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.1 (Tier 1)

Card 2 · Objective 1.1

After your code runs a tool Claude asked for, what must happen before the next request?

Show answer to card 2

Append the tool result to the conversation history. Claude can only reason about the next step from what is in its context.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.1 (Tier 1)

Card 3 · Objective 1.1 · TRAP: name why it is wrong

Tempting wrong answer: "Stop the loop when Claude's reply contains words like 'done' or 'finished'."

Show answer to card 3

Parsing natural language to end the loop is a named anti-pattern. Use stop_reason, which is structured and reliable.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.1 (Tier 1)

Card 4 · Objective 1.1 · TRAP: name why it is wrong

Tempting wrong answer: "Set max iterations to 10 as the way the loop ends."

Show answer to card 4

An arbitrary cap as the primary stopping rule cuts off real work or wastes turns. stop_reason ends the loop; a cap is only a safety net.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.1 (Tier 1)

Card 5 · Objective 1.1

Model-driven decision-making vs a pre-configured decision tree: what is the difference?

Show answer to card 5

In an agent, Claude picks the next tool from context; a decision tree fixes the sequence in code. Agents fit open tasks; fixed trees fit predictable ones.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.1 (Tier 1)

1.2 Orchestrate multi-agent systems with coordinator-subagent patterns

Study objective 1.2 before or after these cards.

Card 6 · Objective 1.2

What is hub-and-spoke in a multi-agent system?

Show answer to card 6

A coordinator manages all communication, error handling and routing between subagents. Subagents never talk to each other directly, which keeps flow observable.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.2 (Tier 1)

Card 7 · Objective 1.2

Do subagents inherit the coordinator's conversation history?

Show answer to card 7

No. Each subagent has isolated context and sees only what the coordinator passes it. Missing facts in its output usually mean missing facts in its prompt.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.2 (Tier 1)

Card 8 · Objective 1.2 · TRAP: name why it is wrong

Tempting wrong answer: "A competitor analysis covered only pricing and skipped product and support, so give the web-search subagent a longer timeout."

Show answer to card 8

If every subagent did what it was asked, the gap is upstream: the coordinator split the topic too narrowly. Fix the decomposition, not a subagent setting.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.2 (Tier 1)

Card 9 · Objective 1.2

Should a coordinator always route every query through the full subagent pipeline?

Show answer to card 9

No. It should analyse the query and invoke only the subagents its complexity needs. Running the full pipeline every time wastes time and cost.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.2 (Tier 1)

Card 10 · Objective 1.2

How does a coordinator make sure a synthesized report has no coverage gaps?

Show answer to card 10

An iterative refinement loop: evaluate the synthesis for gaps, re-delegate targeted queries to search and analysis subagents, re-run synthesis until coverage is enough.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.2 (Tier 1)

Which tool does a coordinator use to spawn a subagent, and what config must allow it?

Card 12 · Objective 1.3 · TRAP: name why it is wrong

Tempting wrong answer: "The synthesis subagent ignores earlier findings, so raise its max_tokens."

Show answer to card 12

The subagent never received those findings. Pass the complete prior outputs in its prompt; a token limit cannot supply context that was never sent.

Card 13 · Objective 1.3

How do you pass findings between agents without losing which source said what?

Show answer to card 13

Use a structured format that separates content from metadata (URL, document name, page). Attribution then survives each hand-off.

Card 14 · Objective 1.3

How do you run three subagents in parallel?

Show answer to card 14

Emit three Task tool calls in one coordinator response. Spreading them across separate turns makes them sequential.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.3 (Tier 1)

Card 15 · Objective 1.3

Should a coordinator's prompt to a subagent give step-by-step procedure or goals?

Show answer to card 15

Goals and quality criteria. Procedural scripts stop the subagent adapting to what it finds.

1.4 Implement multi-step workflows with enforcement and handoff patterns

Study objective 1.4 before or after these cards.

Card 16 · Objective 1.4

Why can't a system prompt alone guarantee an account-ownership check happens before a SIM swap?

Show answer to card 16

Prompt instructions have a non-zero failure rate. When compliance must be deterministic, enforce the order in code with a prerequisite gate.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.4 (Tier 1)

Card 17 · Objective 1.4 · TRAP: name why it is wrong

Tempting wrong answer: "Add 'ALWAYS verify identity first' in capitals to the system prompt."

Show answer to card 17

Louder wording is still a request the model can skip. A programmatic prerequisite that blocks the downstream tool until verification returns is a guarantee.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.4 (Tier 1)

Card 18 · Objective 1.4

What does a programmatic prerequisite gate do?

Show answer to card 18

It blocks a downstream tool call (e.g. close_account) until the prerequisite step has returned the needed value (e.g. a verified account-holder ID).

Source: CCAR-F exam guide v1.0, section 6, task statement 1.4 (Tier 1)

Card 19 · Objective 1.4

What goes in a handoff summary when an agent escalates to a human?

Show answer to card 19

Customer ID, root cause, amounts, and the recommended action, in a structured summary. The human usually cannot see the transcript.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.4 (Tier 1)

Card 20 · Objective 1.4

A customer raises three separate problems in one message. What is the pattern?

Show answer to card 20

Split them into distinct items, investigate each (in parallel where possible) with shared context, then synthesize one unified resolution.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.4 (Tier 1)

1.5 Apply Agent SDK hooks for tool call interception and data normalization

Study objective 1.5 before or after these cards.

Card 21 · Objective 1.5

What does a PostToolUse hook let you do?

Show answer to card 21

Intercept a tool result and transform it (e.g. normalize timestamps or status codes) before the model processes it.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.5 (Tier 1)

Card 22 · Objective 1.5

Which kind of hook blocks a credit-limit increase above a set amount?

Show answer to card 22

A PreToolUse hook: it intercepts the outgoing tool call before it runs and blocks or redirects it, e.g. to human approval. It runs in code every time.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.5 (Tier 1)

Card 23 · Objective 1.5 · TRAP: name why it is wrong

Tempting wrong answer: "MCP tools return dates in three formats, so tell Claude in the prompt to convert them all to ISO 8601."

Show answer to card 23

That relies on the model getting it right every time. A PostToolUse hook normalizes the data deterministically before Claude sees it.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.5 (Tier 1)

Card 24 · Objective 1.5

Hooks vs prompt instructions: which gives deterministic guarantees?

Show answer to card 24

Hooks. Prompt instructions are probabilistic compliance. Choose hooks when a business rule must always hold.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.5 (Tier 1)

1.6 Design task decomposition strategies for complex workflows

Study objective 1.6 before or after these cards.

Card 25 · Objective 1.6

When do you pick prompt chaining over dynamic decomposition?

Show answer to card 25

Prompt chaining (fixed sequential steps) for predictable multi-aspect work; dynamic decomposition when later subtasks depend on what you discover.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.6 (Tier 1)

Card 26 · Objective 1.6

How should a large multi-file code review be decomposed?

Show answer to card 26

Per-file local analysis passes, then a separate cross-file integration pass. One pass over everything dilutes attention.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.6 (Tier 1)

Card 27 · Objective 1.6

How do you decompose an open task like "add comprehensive tests to a legacy codebase"?

Show answer to card 27

Map the structure first, find high-impact areas, then build a prioritized plan that adapts as dependencies are discovered.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.6 (Tier 1)

Card 28 · Objective 1.6 · TRAP: name why it is wrong

Tempting wrong answer: "For an open-ended investigation, write the full list of subtasks up front so the run is predictable."

Show answer to card 28

Open-ended work needs an adaptive plan that generates subtasks from findings. A fixed list misses what you only learn mid-investigation.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.6 (Tier 1)

1.7 Manage session state, resumption, and forking

Study objective 1.7 before or after these cards.

Card 29 · Objective 1.7

How do you continue a specific earlier Claude Code investigation?

Show answer to card 29

--resume <session-name> continues that named session with its prior context (name a session with -n or /rename).

Source: CCAR-F exam guide v1.0, section 6, task statement 1.7 (Tier 1)

Card 30 · Objective 1.7

What is fork_session for?

Show answer to card 30

Creating independent branches from a shared analysis baseline, e.g. to compare two refactoring approaches without re-doing the analysis. fork_session is an Agent SDK option (Python fork_session=True, TypeScript forkSession: true); the CLI equivalent is --fork-session with --resume or --continue.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.7 (Tier 1)

Card 31 · Objective 1.7

Resume or start fresh? When is a new session with a summary better?

Show answer to card 31

When the earlier tool results are stale (files changed a lot). A fresh session with an injected structured summary beats resuming on outdated context.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.7 (Tier 1)

Card 32 · Objective 1.7 · TRAP: name why it is wrong

Tempting wrong answer: "After editing two files, resume the session and ask Claude to re-explore the whole repo."

Show answer to card 32

Wasteful. Resume and tell the agent exactly which files changed so it re-analyses only those.

Source: CCAR-F exam guide v1.0, section 6, task statement 1.7 (Tier 1)

Domain 2: Tool Design and MCP Integration (18%, 23 cards)

2.1 Design effective tool interfaces with clear descriptions and boundaries

Study objective 2.1 before or after these cards.

Card 33 · Objective 2.1

What is the main thing Claude uses to choose between tools?

Show answer to card 33

The tool descriptions. Minimal or overlapping descriptions cause unreliable selection among similar tools.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.1 (Tier 1)

Card 34 · Objective 2.1 · TRAP: name why it is wrong

Tempting wrong answer: "Claude keeps picking the wrong one of two similar tools, so lower the temperature."

Show answer to card 34

Sampling settings do not fix ambiguous descriptions. Rewrite the descriptions (purpose, inputs, outputs, when to use vs the other tool) or rename them.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.1 (Tier 1)

Card 35 · Objective 2.1

What belongs in a good tool description?

Show answer to card 35

Purpose, input formats, example queries, edge cases, outputs and boundaries: when to use it versus similar tools.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.1 (Tier 1)

Card 36 · Objective 2.1

Two tools, analyze_content and analyze_document, are misrouted because their names overlap. What is the rename fix?

Show answer to card 36

Rename to remove the overlap (e.g. analyze_content becomes extract_web_results) and give it a web-specific description.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.1 (Tier 1)

Card 37 · Objective 2.1

One generic tool does several jobs and Claude uses it for the wrong one. What is the split fix?

Show answer to card 37

Split it into purpose-specific tools, each with a clear input/output contract and its own description.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.1 (Tier 1)

Card 38 · Objective 2.1

How can a system prompt break good tool descriptions?

Show answer to card 38

Keyword-sensitive instructions ("whenever the user says 'order', check the customer") create unintended tool associations. Review the prompt for them.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.1 (Tier 1)

2.2 Implement structured error responses for MCP tools

Study objective 2.2 before or after these cards.

Card 39 · Objective 2.2

What is the MCP isError flag for?

Show answer to card 39

Telling the agent a tool call failed, so it can decide how to recover instead of treating the output as data.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.2 (Tier 1)

Card 40 · Objective 2.2

Name the four error categories the guide distinguishes.

Show answer to card 40

Transient (timeout, unavailable), validation (bad input), business (policy violation) and permission. Each needs a different recovery.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.2 (Tier 1)

Card 41 · Objective 2.2 · TRAP: name why it is wrong

Tempting wrong answer: "Return a simple 'Operation failed' for every error to keep the tool interface clean."

Show answer to card 41

Uniform errors stop the agent choosing a sensible recovery. Return errorCategory, isRetryable and a readable description.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.2 (Tier 1)

Card 42 · Objective 2.2

Why include isRetryable: false on a business-rule error?

Show answer to card 42

It prevents wasted retries and, with a customer-friendly explanation, lets the agent tell the user what is going on.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.2 (Tier 1)

Card 43 · Objective 2.2

A search returns zero results. Is that an error?

Show answer to card 43

No, if the query succeeded: it is a valid empty result. An access failure (timeout) is different and needs a retry decision. Report them differently.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.2 (Tier 1)

2.3 Distribute tools appropriately across agents and configure tool choice

Study objective 2.3 before or after these cards.

Card 44 · Objective 2.3

What happens to tool selection when an agent has 18 tools instead of 4-5?

Show answer to card 44

Reliability drops because the decision gets harder. Give each agent only the tools its role needs.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.3 (Tier 1)

Card 45 · Objective 2.3 · TRAP: name why it is wrong

Tempting wrong answer: "The synthesis agent keeps running web searches, so tell it in the prompt not to search."

Show answer to card 45

Remove the search tool from that agent. Tools outside an agent's specialization get misused; scoping tool access is the design fix.

Source: CCAR-F exam guide v1.0, section 6, task statement 2.3 (Tier 1)

Card 46 · Objective 2.3

What are the tool_choice options?

Show answer to card 46

"auto" (may answer in text), "any" (must call some tool), and forced {"type": "tool", "name": "..."} (must call that tool). (Exam wording. Today any and forced tool return 400 on the models listed in the forced-tool-use table in Define tools (https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools, checked 2026-10-21): see exam answer vs today.)

Source: CCAR-F exam guide v1.0, section 6, task statement 2.3 (Tier 1)

Card 47 · Objective 2.3 · TRAP: name why it is wrong

Tempting wrong answer: "To make sure extract_metadata runs first, write 'call extract_metadata first' in the prompt."

Show answer to card 47

That is a request, not a guarantee. Force it with tool_choice {"type":"tool","name":"extract_metadata"}, then handle later steps in follow-up turns. (Exam wording. Today forced tool returns 400 on the models listed in the forced-tool-use table in Define tools (https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools, checked 2026-10-21): see exam answer vs today.)

Card 48 · Objective 2.3

A synthesis agent often needs quick fact checks. Give it the full search agent's tools?

Show answer to card 48

No. Give a scoped cross-role tool (e.g. verify_fact) for the frequent simple case and route complex cases through the coordinator.

2.5 Select and apply built-in tools (Read, Write, Edit, Bash, Grep, Glob) effectively

Grep or Glob: which finds all callers of a function?

Edit fails because the anchor text is not unique. What now?

Reveal conditional answer and repair

Answer to the front: Use stratified error and loss evidence to route the high-risk category rather than rely on the overall average. Aggregate accuracy can hide consequential subgroup failure.

Answer to the paired scene: Define and test a capacity and overflow policy with observable escalation for unresolved review demand. A review design must specify what happens when its required human queue exceeds capacity.

Base choice: A finance extractor has high overall accuracy but weaker rare-currency performance. Evaluate severity-weighted slices on independent holdout and calibrate review thresholds with actual human capacity.

Failure: Distribution drift breaks calibration. Recalibrate on suitable data and evaluate on a separate holdout; do not tune against the final test set.

Nearest alternative: The average can hide dangerous categories; confidence scores alone are not calibrated correctness probabilities.
