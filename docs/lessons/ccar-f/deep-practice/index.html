Picture the application: You have an assistant that receives a customer request, calls a service and returns an explanation, but one step behaves incorrectly. Use this reference area to trace that specific input and expected outcome into the relevant mechanism. Choose a page for the problem instead of memorizing every table at once.

Start with an application · Full learning journey · Learn architecture through eight application cases · Practise 30 decision variants

Your learning route: Start with one application you can picture, then choose a complete situation. Each taught layer shows a failure, asks a technical original exam-style question first, then explains the repair simply after you choose. Use this directory for its particular depth, not as another mandatory course. Return to the complete learning journey.

This section goes deeper than the five CCAR-F lessons. There is one page per exam domain. Each page takes the domain one task statement (TS) at a time, in number order: the core idea, how it works under the hood, the look-alike wrong answers, a worked example and a one-line exam reflex. Five extra pages cut across all domains: the exact signals and error codes, rules for picking between close answers, step-by-step code walk-throughs of the systems the exam scenarios describe, decision charts for the "which option?" moments, and sequence diagrams that show who talks to whom, in order.

Study order: Lesson 0: Orientation: how the Architect exam thinks → Lesson 1: Agentic Architecture and Orchestration → Lesson 4: Prompt Engineering and Structured Output → Lesson 3: Claude Code Configuration and Workflows → Lesson 2: Tool Design and MCP Integration → Lesson 5: Context Management and Reliability, and read each lesson's deep practice page right after it. Use the five cross-domain pages alongside, and read the tie-breaker rules before your first mock. Then move on to the scenario simulations. When a page shows both an exam answer and a today answer, the exam answer vs today table says which one to give on exam day.

Already build with the Claude API and Claude Code? Start with the tie-breaker rules and the conditions sheet, then open the domain pages only for the task statements you miss; the full fast path is on the lessons page.
