Lab 04 — Same task, three API modes: real time, cached and batch (CCDV-F, CCAR-P)

Supports: CCDV-F Lesson 1: Applications and Integration, Lesson 2: Model Selection and Optimization · CCAR-P Lesson 6: Models, Prompting and Context · Time: 2 hours · Needs: Python 3.10+, pip install anthropic, an API key (see the laptop note in lab 02).

Done when: you have a small table of latency, input tokens, cached tokens and relative cost for the same 20 requests run three ways, and you can say in one sentence when each mode wins.

Setup

  • Choose one task, such as "classify this support email into 1 of 6 categories and give a reason".
  • Write a long, fixed system prompt of several thousand tokens: the policy, category definitions and examples. Keep it the same on every request.
  • Make 20 short emails as the varying input.

Run A — real time, no caching

  • Call client.messages.create(...) 20 times.
  • Record wall-clock time and response.usage.input_tokens / output_tokens.
  • Try stream=True once and note the time to the first token versus the full response.

Run B — real time with prompt caching

  • Put the fixed system prompt first, with cache_control: {"type": "ephemeral"} on its last block.
  • Rerun the 20 requests. From the second request on, check usage.cache_read_input_tokens against cache_creation_input_tokens.
  • The cache matches only an identical prefix. Change one word in the system prompt and watch the reads drop to zero.
  • Minimum cacheable length and cache lifetime vary. Check the prompt caching docs.

Run C — Message Batches API

  • Submit all 20 requests as one batch with client.messages.batches.create(requests=[...]), giving each one a custom_id.
  • Poll until the batch ends, then read the results by custom_id. Results can come back in any order.
  • Note that batch trades speed for cost: results arrive asynchronously, within a window of up to 24 hours. See the batch processing docs.

A real timea user is waiting, and every prompt is different

Use the current pricing page to turn tokens into cost. Don't use remembered numbers.

Bonus

  • Add simple retry with backoff for 429 (rate limited) and overloaded errors.
  • Rerun A on a smaller and a larger model tier, and compare quality on 5 emails.

Sources: CCDV-F official exam guide v1.0, Domain 2 "Claude API Mechanics" and Domain 5 "Cost and Token Management"; the docs linked above; streaming; rate limits.
