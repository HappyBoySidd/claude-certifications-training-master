What you'll build and why

Related technical reference · execution-time authorization / prerequisite gate

You'll build a tiny inventory tool server, plug it into Claude Code, and put guard rails around it. The point is to feel, hands-on, where a rule has to live so it really holds.

you ──> Claude Code ──(MCP)──> inventory server ──> inventory.json
             │
             ├── PreToolUse hooks: block rm -rf, ask before big reservations
             ├── CLAUDE.md + .claude/rules/: project memory
             └── restock-report skill: runs in its own forked context

Words you'll meet, in plain terms:

  • MCP (Model Context Protocol): a standard way for an app like Claude Code to talk to a "server" program that offers tools.
  • MCP server: a small program that lists tools and runs them when asked.
  • Tool: one action the model can ask for, such as get_item.
  • isError: a flag on a tool result that says "this call failed". Without it, the client treats the result as a success.
  • Scope: where a server is registered. Project scope lives in .mcp.json and is shared with the team; user scope lives in your own ~/.claude.json.
  • Hook: a script Claude Code runs at a fixed moment, such as just before a tool call (PreToolUse). Its answer can block or pause the call. The model can't talk its way past it.
  • Skill: a folder with a SKILL.md file that packages instructions Claude Code can run on request.
  • Forked context (context: fork): the skill runs in a separate sub-context, so its working notes don't fill your main conversation.
  • Plan mode: Claude Code proposes a plan and waits for your OK before it edits anything.

Task numbers refer to the task statements in the official exam guide.

Steps

1. A three-tool server

Practises: tasks 2.1 and 2.2.

Write a server with the official Python MCP SDK (FastMCP):

  • list_items(): returns every SKU with its name, so the agent can find SKUs it wasn't told.
  • get_item(sku): reads one item from a small local JSON file.
  • reserve_item(sku, qty): a write action. It checks stock and returns an error if there isn't enough.

Sample inventory.json, next to server.py:

{
  "SKU-001": {"name": "Blue mug", "qty": 12},
  "SKU-002": {"name": "Desk lamp", "qty": 3},
  "SKU-003": {"name": "Notebook", "qty": 0}
}

At start-up, the server reads INVENTORY_TOKEN from os.environ. If it's missing or empty, every tool call is refused with a permission error. (Empty matters: see step 2.)

Return errors as a result with isError: true. A plain returned dict reaches the client as a success, so the agent can't tell anything went wrong. Inside that error result, put a body with these fields:

  • errorCategory: transient, validation or permission
  • isRetryable: for example false for "not enough stock"
  • a plain sentence on what to do instead

errorCategory and isRetryable are the fields the CCAR-F exam guide (task 2.2) describes. They are your body fields, not fields defined by the MCP spec. The spec only gives you isError and the content.

Example error body for "reserve 1,000 of SKU-001":

{
  "errorCategory": "validation",
  "isRetryable": false,
  "message": "Only 12 of SKU-001 are in stock. Ask the user whether to reserve 12 or fewer."
}

2. Register it for the whole team

Practises: task 2.4.

Create .mcp.json at the repo root, which is committed, so everyone gets the same server. Secrets come in through environment variables:

{
  "mcpServers": {
    "inventory": {
      "command": "python3",
      "args": ["server.py"],
      "env": { "INVENTORY_TOKEN": "${INVENTORY_TOKEN:-}" }
    }
  }
}

Use python3: on macOS a bare python often doesn't exist. Run claude from the repo root, or put an absolute path to server.py in args.

Why ${INVENTORY_TOKEN:-} and not ${INVENTORY_TOKEN}: if the variable is unset, Claude Code still loads the config, shows a warning in claude mcp list, and passes the literal text ${INVENTORY_TOKEN} to the server. Your server would then see a "token" that isn't empty and might accept it. The :- form with nothing after it expands to an empty string instead, and your server treats empty as missing (Claude Code MCP docs, Tier 1, check the current docs).

Personal or experimental servers go in your user config, ~/.claude.json. Add a tiny echo server there. Save this as ~/mcp-echo/echo_server.py:

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("echo")

@mcp.tool()
def echo(text: str) -> str:
    """Return the text unchanged. Use only to test that MCP is wired up."""
    return text

if __name__ == "__main__":
    mcp.run()

Then register it at user scope (use your own absolute path):

claude mcp add --scope user echo -- python3 /Users/YOU/mcp-echo/echo_server.py

How you know it worked: claude mcp list shows both echo and inventory, and /mcp inside Claude Code shows both as connected at the same time.

3b. The restock-report skill

Create .claude/skills/restock-report/SKILL.md with context: fork.

Careful: allowed-tools pre-approves the tools you list, so Claude can use them without asking. It does not stop the skill from using other tools. To actually restrict it, either:

  • list the tools to block in disallowed-tools, or
  • point the skill at a narrow subagent with agent: (together with context: fork), and give that subagent only the read tools. A report should never be able to reserve stock.

The second route is cleaner here. A sketch (check the field names in the skills docs and subagents docs, Tier 1, check the current docs):

---
name: restock-report
description: List items with qty under 5 and suggest a restock amount for each.
context: fork
agent: inventory-reader
allowed-tools: mcp__inventory__list_items, mcp__inventory__get_item
---
Call list_items to get every SKU, then get_item for each one, and report which are under 5.

…with .claude/agents/inventory-reader.md whose tools: list holds only mcp__inventory__list_items and mcp__inventory__get_item (no reserve_item). (A plain command in .claude/commands/ also works; the skill is what the guide tests.)

4. A guardrail hook

Practises: tasks 1.5 and 3.2.

In .claude/settings.json, add two PreToolUse hooks:

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "python3 .claude/hooks/block_rm.py" }]
      },
      {
        "matcher": "mcp__inventory__reserve_item",
        "hooks": [{ "type": "command", "command": "python3 .claude/hooks/ask_big_reserve.py" }]
      }
    ]
  }
}

Hook 1, block_rm.py. It reads the tool call as JSON on stdin, takes tool_input.command, and, if it matches a recursive force delete (rm -rf, rm -fr, rm -r -f), prints a reason to stderr and exits with code 2. Exit code 2 blocks the call, and the stderr text is what gets fed back to Claude. A plain substring check for rm -rf misses the other two.

import json, re, sys

data = json.load(sys.stdin)
cmd = data.get("tool_input", {}).get("command", "")
# YOUR CODE: a regex that catches rm with both -r and -f, in any order or split across flags
if re.search(r"YOUR_PATTERN", cmd):
    print("Blocked: recursive force delete. Delete specific files instead.", file=sys.stderr)
    sys.exit(2)
sys.exit(0)

Hook 2, ask_big_reserve.py. When tool_input.qty is over 10, it prints this JSON to stdout and exits 0 (exit 0 is the intended code when you print JSON; exit 2 would block the call no matter what the JSON says):

{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "ask",
    "permissionDecisionReason": "Reserving more than 10 units needs a human OK."
  }
}

permissionDecision takes allow, deny, ask or defer. For 10 or fewer, print nothing and exit 0. See the hooks docs (Tier 1, check the current docs) for the exact input and output format.

The approval hook is a pattern the CCAR-F, CCDV-F and CCAR-P guides all cover: a hard rule enforced in code, not in the prompt. That's why this one lab supports all three exams.

How you know it worked: run /hooks and see both hooks listed. Step 5 tests them.
